# my-finish-branch

ユーザーによる動作確認が完了した現在の作業ブランチ (`feat/`・`fix/` など) を、main に取り込んで完了させる。
以下の手順を順に実行し、いずれかの手順で失敗した場合はその時点で中断して状況を報告する (以降の手順には進まない)。

## 手順

### 0. 前提の確認

`git branch --show-current` で現在のブランチを確認する。main ブランチ上の場合はマージ対象がないため、何もせずにその旨を報告して終了する。
以降、現在のブランチを `<branch>` と表記する。

### 1. チェック

`.claude/docs/LOCAL_TEST.md` に従い、変更箇所 (`git diff main...HEAD` と未 commit の変更) に応じたチェックを実行する。

- フロントエンドのみ・バックエンドのみの変更であれば、該当するセクションのみでよい
- このセッション中で最後にチェックを実行してから変更がない場合は省略してよい (省略した旨は最後の報告に含める)
- フォーマッタや `lint:fix` がファイルを修正した場合、その修正も手順 3 の commit に含める

### 2. リリースビルド

```sh
npm run tauri build
```

実行には数分かかるため、Bash のタイムアウトは最大 (600000ms) にする。

### 3. commit

未 commit の変更がなければこの手順は省略する。

commit の対象:

- git 管理下のファイルの変更 (staged / unstaged) はすべて含める
- 未追跡ファイル (`??`) は、このセッション中に Claude が作成したもののみ含める。それ以外の未追跡ファイルがある場合は、含めるかどうかをユーザーに確認する

コミットメッセージは既存の履歴 (`git log`) の形式に合わせて作成する (`feat:` / `fix:` などの接頭辞を付けた英語の 1 行 + 必要に応じて本文)。メッセージについてユーザーへの事前確認は不要で、最後の報告で示す。

### 4. main へのマージ

```sh
git checkout main
git merge --no-ff <branch> -m "Merge branch '<branch>'"
```

コンフリクトが発生した場合は、`git merge --abort` で元に戻した上で状況を報告する。

### 5. ブランチの削除

- ローカル: `git branch -d <branch>`
- リモート: `git ls-remote --heads origin <branch>` で存在を確認し、存在する場合のみ `git push origin --delete <branch>` で削除する

### 6. push

```sh
git push origin main
```

リモートの main が先に進んでいるなどで push が拒否された場合は、強制 push はせずに状況を報告する。

### 7. 報告

以下を報告して終了する。

- 各手順の結果 (チェック・リリースビルドの成否と省略有無、ビルド成果物のパス、commit のハッシュとメッセージ、マージコミットのハッシュ、削除したブランチ (ローカル / リモート)、push した範囲)
- commit に含めなかった未追跡ファイルがあればその一覧
- CI の結果は確認していないため、必要に応じて `/my-check-workflow` で確認できる旨
