# my-codex-review

現在のブランチの変更を Codex CLI (`codex review`) にレビューさせ、指摘への対応をユーザーと協議した上で修正する。
レビューは 1 ループで完結させる。再レビューが必要な場合はユーザーが改めてこのスキルを実行する。

## 引数

- 第 1 引数: レビュー対象の差分のベースブランチ。省略時は `main`
- 以降、ベースブランチを `<base>` と表記する

## 手順

### 1. 未コミット変更の確認

`git status --short` で git 管理下のファイルの変更 (staged / unstaged) を確認する。未追跡ファイル (`??`) は無視する。

変更がある場合、レビュー対象は commit 済みの内容のみであることを伝えた上で、変更の概要を示して以下を選んでもらう:

- commit してからレビューする (commit 対象のファイルもあわせて確認する)
- このまま (commit 済みの内容のみで) レビューする

### 2. Codex にレビューを依頼

`codex review` では `--base` と独自プロンプトを併用できないため、プロンプト内で差分範囲を指定する。
実行には数分かかるため、Bash のタイムアウトは最大 (600000ms) にし、出力はスクラッチパッドのファイルに保存する。

```sh
codex review "<base>...HEAD の差分 (git diff <base>...HEAD) をレビューしてください。リポジトリに CLAUDE.md がある場合は、そこに記載されたコーディングルールも踏まえてレビューしてください。" > <scratchpad>/codex-review.txt 2>&1
```

出力の末尾 (最後の `codex` 行以降) が最終的なレビュー結果。途中の出力は Codex の作業ログ。

- Codex のサンドボックス制約でテスト実行に失敗した旨が出力されても問題としない (テストは手順 5 で Claude 側で実行する)
- 差分範囲を正しく扱えていない様子 (無関係なファイルへの言及など) があればユーザーに報告する

### 3. 指摘の検証

指摘が 0 件なら、その旨をユーザーに報告して終了する。

指摘がある場合、各指摘について該当コードを読み、妥当性を判定する:

- 妥当: 実際に問題が起こりうる
- 誤検知の可能性あり: コード上そうならない、または前提が誤っている

誤検知と判断したものも除外せず、手順 4 の論点に含める (Claude の判定が誤っている可能性をユーザーが拾えるようにするため)。

### 4. 一問一答で対応を協議

最初に指摘の一覧 (論点数と各論点の要約) を示し、その後 1 論点ずつ協議する。各問いは以下の形式で出力し、ユーザーの回答を待ってから次の論点に進む:

- おおよその残り問数 (協議の中で追加の論点が生じた場合は増減してよい)
- Codex の指摘内容 (要約) と該当箇所 (`ファイルパス:行番号`)
- Claude の検証結果 (妥当 / 誤検知の可能性あり) とその根拠
- 選択肢 (例: 修正する / 別の方法で修正する / 見送る)。修正案がある場合は具体的な修正内容を示す
- 推奨する選択肢とその理由

全論点の協議が終わったら、決定内容の一覧を示す。

### 5. 修正・確認・commit

「修正する」と決まった論点がない場合は、ここで終了する。

ある場合は以下を行う:

1. 決定内容に従って修正する (必要に応じてテストも追加・修正する)
2. CLAUDE.md や関連ドキュメントに記載のフォーマット・lint・型チェック・テスト等を、変更箇所に応じて実行する
3. commit する (コミットメッセージには対応した指摘の内容を含める)

完了後、対応内容を報告して終了する。再レビューは行わない。
